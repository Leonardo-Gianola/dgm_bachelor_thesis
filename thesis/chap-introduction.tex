\chapter{Introduction}
\label{chap:introduction}

Language models have become capable enough at programming that they are
now packaged as autonomous coding agents, programs that have a goal, use
tools like searching and editing files, run tests, and iterate in a
reason-act loop~\cite{Yao:23}.
SWE-bench~\cite{Jimenez:24} provides a standard testbed of real GitHub
issues for evaluating such agents. The Darwin G{\"o}del
Machine~\cite{Sakana:25} uses this idea to build a system that lets a
coding agent rewrite its own implementation. Each generation, a
population of agents proposes modifications to its own source code, the
new children agents are evaluated on SWE-bench, and the most promising
offspring are kept in an archive that seeds the next generation. One of
the problems of this system is that most of the compute invested goes
into evaluation, and that is where this thesis intervenes.

\section{Problem}

Evaluation is the chokepoint. Each candidate child is executed against a
benchmark of real GitHub issues inside Docker, which is slow (minutes
per task) and monetarily expensive (paid LLM API calls plus container
overhead). Most generated children create negative modifications to
their own code, and this can be observed on a subset of the benchmark,
in the first tasks the agent is fed. Spending more than the necessary
task budget on a bad child is wasteful.
The Darwin G{\"o}del Machine ships with a fixed three-stage evaluation
pipeline (small, medium, and full), which this thesis treats as the
baseline scheduler. It is a partial mitigation, but blind: it uses
thresholds rather than ranks across the group of children. This baseline
still wastes tasks on children that present no improvement, which
makes the whole system inefficient.

\section{Research Question}

\begin{quote}
\emph{Can multi-fidelity evaluation schedulers reduce the cost per
improvement of the Darwin G{\"o}del Machine without lowering the
accuracy of the evolved agents?}
\end{quote}

To answer this, we implement and compare four schedulers: a sequential
baseline, Hyperband~\cite{Li:18}, ASHA~\cite{Li:20}, and a blind
genetic algorithm~\cite{Holland:75}. All four schedulers share the
same model (\texttt{minimax-m2.5}~\cite{MiniMax:25}), benchmark
(\texttt{swe\_verified\_mini}, a 50-task subset of SWE-bench
Verified~\cite{Jimenez:24}), initial archive, and seed. The scheduler is
the only independent variable.

\section{Contributions}

\begin{itemize}
  \item \textbf{Engineering.} An open-source Darwin G{\"o}del Machine
    fork with four pluggable schedulers (baseline, Hyperband, ASHA,
    genetic algorithm) on \texttt{swe\_verified\_mini}, with the entire
    scheduler layer isolated to \texttt{schedulers.py}.
  \item \textbf{Operational guards.} Three guards that protect long
    evolutionary runs from silent budget burn: a compile-time argparse
    guard that rejects self-modifications removing required CLI flags,
    an empty-patch retry loop with a strengthened prompt, and a Docker
    per-image build lock with exponential-backoff startup retry.
  \item \textbf{Empirical.} Under a fixed per-generation task budget on
    \texttt{swe\_verified\_mini}, across four single-seed pilot runs,
    the blind genetic algorithm reached a peak of 70.59\% at the lowest
    cost (\$26 total, \$0.71 per accuracy point gained); Hyperband
    reached the highest peak of 75.86\% (generation 3) but at 73\%
    higher cost; ASHA ran 32\% faster in wall clock than Hyperband, but
    its peak regressed across generations. All results are single seed
    (n=1) and descriptive.
  \item \textbf{Methodological.} A coverage-reliability measurement
    layered on top of the existing accuracy metric: the gap between
    each scheduler's intended workload (planned tasks per child summed
    over the run) and its actual exposure (predictions SWE-bench
    produced) reveals two independent failure modes
    (stage-cumulative aggregation and silent crash skips) that the
    headline rate alone does not surface.
\end{itemize}
